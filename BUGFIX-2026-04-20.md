# GoClaw Bugfix Report — 20/04/2026

## Bug 1: Browser tool "context canceled" khi mở tab

**Triệu chứng:** Bot gọi browser tool để mở tab mới → lỗi `open tab: context canceled`. Chrome container healthy, CDP hoạt động bình thường nhưng GoClaw không thể mở tab.

**Nguyên nhân:** Trong `pkg/browser/browser.go`, hàm `Start()` tạo Rod browser với `connectCtx` (timeout 15 giây):

```go
connectCtx, connectCancel := context.WithTimeout(ctx, 15*time.Second)
defer connectCancel()

b := rod.New().Context(connectCtx).ControlURL(controlURL)
b.Connect()
m.browser = b
```

Khi `Start()` return, `defer connectCancel()` hủy `connectCtx`. Rod giữ context này cho **tất cả** thao tác sau đó (OpenTab, Navigate, Snapshot...). Kết quả: mọi browser operation sau `Start()` đều nhận `context.Canceled`.

**Fix:** Sau khi connect thành công, đổi browser context sang `context.Background()`. Mỗi operation tự áp timeout riêng qua `actionTimeout`.

```go
// Trước (lỗi)
m.browser = b

// Sau (fix)
m.browser = b.Context(context.Background())
```

**File:** `pkg/browser/browser.go` dòng 167

## Bug 2: Screenshots "file not found" gây bot treo

**Triệu chứng:** Sau khi restart container, bot bị treo không phản hồi. Log hiện hàng loạt warning:

```
vision: failed to read image file
  path="...screenshot_xxx.png?ft=1LtilN3L...abc123.1776684483"
  error="no such file or directory"
```

**Nguyên nhân:** Trong `internal/agent/media.go`, khi load ảnh từ conversation history, file path chứa query string `?ft=<token>` (do file serving API thêm vào). Hàm `os.ReadFile()` nhận path nguyên gốc kèm query string → không tìm được file trên filesystem.

```go
// Path thực tế trên disk:
/app/workspace/.../screenshot_xxx.png

// Path trong history (có query string):
/app/workspace/.../screenshot_xxx.png?ft=1LtilN3L...abc123.1776684483
```

Bot cố load 10+ ảnh cũ mỗi lần chạy → tất cả fail → tốn thời gian + context window.

**Fix:** Strip query string VÀ `/v1/files` API prefix trước khi đọc file:

```go
// Trước (lỗi)
data, err := os.ReadFile(f.Path)
// f.Path = "/v1/files/app/workspace/.../screenshot.png?ft=abc123"
// → file not found

// Sau (fix)
cleanPath := f.Path
if idx := strings.IndexByte(cleanPath, '?'); idx != -1 {
    cleanPath = cleanPath[:idx]
}
cleanPath = strings.TrimPrefix(cleanPath, "/v1/files")
data, err := os.ReadFile(cleanPath)
// cleanPath = "/app/workspace/.../screenshot.png"
// → file found ✓
```

**File:** `internal/agent/media.go` dòng 39

## Bug 3: Telegram bot không nhận tin nhắn

**Triệu chứng:** Bot Telegram không phản hồi tin nhắn. Log hiện:

```
ERROR failed to start channel channel=giahan1-bot
  error="validate telegram bot: ... dial tcp 149.154.166.110:443: i/o timeout"
```

**Nguyên nhân:** Khi Docker khởi động, mạng chưa ổn định → kết nối đến `api.telegram.org` bị timeout → channel `giahan1-bot` fail to start và không polling tin nhắn. GoClaw không tự retry start channel sau khi fail.

**Fix tạm:** Restart container sau khi mạng ổn định:

```bash
docker compose restart goclaw
```

**Gợi ý fix lâu dài:** Thêm retry logic trong channel startup — nếu fail thì retry sau 30s/60s/120s (exponential backoff).

## Bug 4: Bot treo khi dùng browser tool với trang nặng (Facebook)

**Triệu chứng:** Khi bảo bot mở Facebook, bot gọi browser tool rồi đứng im không phản hồi. Log chỉ hiện `tool call` mà không có `run.completed`. Các tin nhắn tiếp theo bị queue ("new task queued behind active run").

**Nguyên nhân:** 2 vấn đề kết hợp:

1. **`actionTimeout` mặc định 30s quá dài** — Facebook load JS liên tục, `WaitStable(300ms)` không bao giờ ổn định → tool call block hết 30s → bot chậm phản hồi
2. **AX tree snapshot quá lớn** — Facebook trả về 1300+ accessibility nodes (~420KB). Mỗi lần bot gọi snapshot, toàn bộ AX tree nằm trong conversation history → tích lũy nhanh qua nhiều lần gọi

**Hậu quả:** Session tích lũy ~7 triệu tokens (input+output cộng dồn). Mặc dù compaction hoạt động đúng (nén khi >75% context window), mỗi request vẫn tốn 200-350K tokens vì bot gọi browser tool 5-7 lần.

**Fix:**

1. Giảm `actionTimeout` từ 30s → 15s (`pkg/browser/browser.go` dòng 77):
```go
// Trước
actionTimeout: 30 * time.Second,

// Sau
actionTimeout: 15 * time.Second,
```

2. Khi session bị phình, reset bằng SQL:
```sql
UPDATE sessions
SET messages = '[]'::jsonb,
    input_tokens = 0,
    output_tokens = 0,
    summary = NULL
WHERE session_key = 'agent:<agent-key>:<channel>:direct:<user-id>';
```

Sau đó restart GoClaw:
```bash
docker compose restart goclaw
```

**Gợi ý fix lâu dài:**
- Giới hạn kích thước tool output (truncate AX tree > 4000 chars)
- Tự động dọn screenshot cũ khỏi conversation history sau N turns
- Thêm retry logic với timeout ngắn hơn cho trang nặng

**File:** `pkg/browser/browser.go` dòng 77

## Bug 5: Agent summoning fail với một số model Codex

**Triệu chứng:** Agent Curie hiện "Failed", Newton stuck ở "Summoning..." trên dashboard.

**Nguyên nhân:** GoClaw dùng model của agent để chạy summoning (tạo identity files). Model `cx/gpt-5.1-codex-mini` không hỗ trợ với ChatGPT account:

```
gpt-5.1-codex-mini model is not supported when using Codex with a ChatGPT account
```

**Fix:** Đổi model sang model được hỗ trợ rồi resummon:

```bash
TOKEN="<gateway-token>"

# Đổi model
curl -X PUT "http://localhost:18790/v1/agents/<agent-id>" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-GoClaw-User-Id: <user-id>" \
  -H "Content-Type: application/json" \
  -d '{"model": "cx/gpt-5.3-codex"}'

# Resummon
curl -X POST "http://localhost:18790/v1/agents/<agent-id>/resummon" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-GoClaw-User-Id: <user-id>"
```

Nếu summoning vẫn stuck, force activate qua DB:
```sql
UPDATE agents SET status='active' WHERE agent_key='<key>';
```

**Gợi ý fix lâu dài:** Khi summoning fail, GoClaw nên fallback sang model khác hoặc retry với model mặc định.

## Bug 6: Bot im lặng khi session chạm 100% context window

**Triệu chứng:** Bot hoàn toàn không phản hồi, không báo lỗi. User nhắn tin → không ai trả lời. Log chỉ hiện:

```
WARN "still over budget after compaction" tokens=210000 budget=200000
```

**Nguyên nhân:** Trong `internal/pipeline/prune_stage.go`, khi history tokens > budget sau compaction, pipeline set `AbortRun` và dừng ngay. Nhưng **không gửi bất kỳ tin nhắn nào** cho user biết tại sao bot dừng.

```go
// prune_stage.go:196-198
if historyTokens > budget {
    slog.Warn("still over budget after compaction", "tokens", historyTokens, "budget", budget)
    s.result = AbortRun  // ← dừng im, user không biết
}
```

**Tình huống dễ gặp:**
- Dùng browser tool nhiều lần (mỗi lần snapshot ~4000 chars)
- Session tích lũy qua nhiều ngày không reset
- Gửi/nhận nhiều ảnh lớn

**Fix tạm:** Reset session khi bot im:

```sql
UPDATE sessions
SET messages = '[]'::jsonb,
    input_tokens = 0, output_tokens = 0,
    summary = NULL
WHERE session_key = 'agent:<agent-key>:<channel>:direct:<user-id>';
```

```bash
docker compose restart goclaw
```

**Gợi ý fix lâu dài:** Khi `AbortRun` do over budget, gửi tin nhắn cho user:

```
"Xin lỗi, cuộc hội thoại quá dài. Em đã tạo session mới, anh nhắn lại nhé."
```

Rồi tự động reset session thay vì im lặng.

**File:** `internal/pipeline/prune_stage.go` dòng 196-198
